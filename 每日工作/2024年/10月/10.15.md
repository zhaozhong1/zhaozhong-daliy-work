### 1. MySQL数据库 

#### 1. 索引

1. 什么字段适合建索引
   1. 频繁用于条件查询的字段适合建立索引
   2. 用于连接的字段适合建立索引
   3. 频繁 `GROUP BY` 、`ORDER BY`的字段适合建立索引
   4. 字段有唯一性限制的，比如商品编码
2. 什么时候不适合建立索引
   1. `WHERE` 条件，`GROUP BY`，`ORDER BY` 里用不到的字段
   2. 字段中存在大量重复数据的不建立索引。如男/女
   3. 表数据太少时，不需要建立索引
   4. 经常更新的字段不用创建索引

#### 2. SQL语法复习

#### 1. 连接

left join : 左表的on字段保留

right join : 右表的on字段保留

inner join : 保留左右表的交集on字段

full join ：保留左右表的并集on字段

union/union all : 拼接两个查询字段的行 union是去重，union all 是不去重

#### 2. GROUP BY

GROUP BY分为 SQL 1992 和 SQL 1999 标准

SQL 1992 对GROUP BY 的标准更严格，规定查询字段不可超出 GROUP BY 的字段。

SQL 1999 为了兼容数据库，将这项设置关闭了。仍可以通过开启：

```sql
SET sql_mode = 'STRICT_TRANS_TABLES,NO_ZERO_IN_DATE,NO_ZERO_DATE,NO_ENGINE_SUBSTITUTION,ONLY_FULL_GROUP_BY';
```

#### 2. Completable Future API测试

#### Future + callable的用法

```java
public class Demo implements Callable<Integer> {

    public static void main(String[] args) throws Exception {
        Demo demo = new Demo();
        FutureTask<Integer> task = new FutureTask<>(demo);
        new Thread(task).start();
        System.out.println(Thread.currentThread().getName() + ":" + "执行");
        Integer integer = task.get();
        System.out.println(integer);
    }

    @Override
    public Integer call() throws Exception {
        Thread.sleep(10000);
        return 1;
    }
}
```

get是阻塞的。当call的睡眠线程未醒，会一直阻塞在get中。
