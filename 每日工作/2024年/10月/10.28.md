##### 1. JVM - GC √

1. CMS : CPU占用高的垃圾回收器
   1. STW 初始标记 记录GCRoot直接到达对象
   2. 并发标记：顺着已标记对象继续向下标记
   3. 重新标记：修正在并发标记时引用的变动
   4. 并发清理：对未记录的地方进行清扫
2. G1：效率十分高的垃圾回收器
   1. STW 初始标记
   2. 并发标记
   3. 最终标记
   4. 筛选回收

##### 2. JVM - 类加载

1. 双亲委派 :
   1.  即 在类加载时不在本类加载器中加载，而是先询问父类加载器有无该类，自顶向下查找。
   2. 好处是能够保证类是安全的。如果本包或依赖中有一个String类型，并且加载了该类型，那么就会导致使用的是这个假的String类型。
   3. 打破双亲委派：重写loadClass()。
2. 类加载器的作用：加载Java的字节码到JVM中。生成一个Class对象在堆区，以及Klass对象在元空间区。
3. 类加载过程：
   1. 加载：通过类加载器将类从字节码文件加载为内存数据。
   2. 链接：
      1. 验证：验证该类对象是否正常。
      2. 准备：正式为类变量分配内存并设置类变量初始值的阶段。
      3. 解析：是虚拟机将常量池内的符号引用替换为直接引用的过程。即直接指向内存位置。
   3. 初始化：这一步 JVM 才开始真正执行类中定义的 Java 程序代码
   4. 类卸载满足三个要求才会GC：
      1. 堆中没有该实例
      2. 该类没有被引用
      3. 该类的类加载器被GC

#### 1. 死锁

##### 死锁发生的条件

1. 互斥条件：多个线程不能同时使用同一个资源
2. 持有并等待条件：一个线程持有资源1，同时申请资源2，但资源2已被持有，需等待资源2释放
3. 不可剥夺条件：在自己用完之前不可被其他线程获取
4. 环路等待条件：两个线程获取资源的顺序已成为循环链

##### 避免死锁

仅需破坏一个条件即可。

最常见的是使用资源有序分配法破坏环路等待条件。即保证线程资源的获取顺序一致。

##### 2. 如何理解SpringIoC

SpringIoC实际上是定义了一个IoC容器，可以理解为一个工厂，然后所有被声明为Bean的类，都会在这个IoC容器中创建。

- 为什么要这样做？这样做有什么好处：
  1. 将创建对象的责任交给外部管理，并通过依赖注入的形式归还，使依赖解耦。
  2. 开发者不需要管对象的实现，只需从IoC中拿即可,拿new做对比，想要创建这个对象，你还需要去看这个对象的构造方法，对比区别等等。

##### 3. 如何理解AOP

Spring AOP 解决了非业务代码抽取的问题。

AOP底层用的是CGLIB和JDK Proxy，内部实现依赖的是BeanPostProcesser。所谓面向切面编程，就是能够在方法前后增加非业务代码，和动态代理不同的是，AOP可以一劳永逸，不用自己去管理代理。
