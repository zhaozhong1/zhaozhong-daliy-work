# HTTP 知识点

## 1. HTTP 协议基础

### HTTP 协议是什么？它的主要作用是什么？

HTTP，翻译叫做超文本传输协议，他主要用于传输网页、文件等资源。

### HTTP 和 HTTPS 有什么区别？

HTTPS是HTTP的安全版本。HTTPS通过证书、对称加密和非对称加密实现信息在传输中的安全。

### 什么是 HTTP 请求和响应？

HTTP请求是由请求发送端发起的一个包含请求行、请求头、请求体、的HTTP报文。

HTTP响应是请求接收端在收到HTTP请求时向发送端回应的一个包含响应行、响应头、响应体的HTTP报文。

### HTTP 的请求方法有哪些？每种方法的特点是什么？

- GET 用于获取网络资源

- POST 用于向网络资源提交数据

- DELETE 用于删除网络资源

- PUT 用于向网络资源进行更新

- OPTIONS 用于对服务器进行嗅探
- PATCH 用于向部分网络资源进行更新
- TRACE 用于http请求的测试和诊断
- HEAD HEAD方法在各个方面均与GET方法相同，唯一不同之处在于，服务器收到HEAD请求，不会将body里的内容返回给客户端

### HTTP 状态码有哪些？如何分类？常见的状态码有哪些？

HTTP有1/2/3/4/5的状态码。

- 1：信息性状态码。
  - 100 继续
  - 101 切换协议
- 2：成功状态码。
  - 200 OK 成功
  - 201 已创建
  - 202 已接受
  - 204 无内容
- 3：重定向状态码。301：资源已永久迁移。 302：资源暂时迁移。 304：缓存资源
- 4：客户端错误状态码：
  - 400 bad request，表示请求响应不对接。 
  - 401 Unauthorized 未授权
  - 403 forbidden 无权限
  - 404 NOT FOUND 资源路径错误。
- 5：服务器错误状态码：
  - 500 Internal Server Error 内部错误
  - 503 服务不可用
  - 504 网关问题

### 什么是 Cookie 和 Session？它们有什么区别？

Cookie 是浏览器提供的，用于弥补HTTP无状态的一个技术。服务端可以为浏览器注入Cookie来标识请求。

Session是服务器提供的，用于保存用户状态的一个技术。服务器端可以保存该用户的数据作为标识，并返回sessionId给浏览器cookie供下次访问。

#### 区别： *

- 数据存储：
  - Cookie存在浏览器端，数据量通常很小。
  - Session存在服务器端，数据量可以存的更大。
- 安全性：
  - Cookie更容易受到跨站脚本攻击（XSS）和跨站请求伪造（CSRF）等安全问题。因此敏感信息不应该存在Cookie中。
  - Session 可能会遭到会话劫持的攻击。
- 生命周期：
  - cookie可以设置过期时间。可以是会话级（关闭浏览器即删除）或持久性（在特定时间过期）。
  - session的生命周期通常由会话管理器控制，可以在一定时间内保持活动状态，但会话通常在一段时间后会过期。

### HTTP 1.1 和 HTTP 2.0 的主要区别是什么？

1. 通过Stream技术使请求可以并行传输，并且也解决了对头阻塞的问题。
2. 服务器推送
3. 请求头压缩
4. 二进制格式

### 为什么 HTTP 是无状态的？它的无状态性带来哪些挑战？

HTTP无状态性会导致会话的保持更加复杂。

因为会话通常是有上下文的，无状态无法确认会话过程中请求是否被劫持，也就是安全性问题。

如果要解决这个问题，就需要频繁在请求中要求用户信息，牺牲用户体验。

因此通过cookie和session解决无状态问题。

## 2. HTTP 请求和响应

### HTTP 请求的结构是什么？包括哪些部分？

1. 请求行：包含HTTP的版本、HTTP方法
2. 请求头：包含浏览器信息、请求类型content-type，包长度，本地ip地址等。
3. 请求体：GET请求一般不会包含请求体。请求体用于放表单信息。

### HTTP 响应的结构是什么？包含哪些部分？

1. 响应行
2. 响应头
3. 响应体

### 什么是请求头、响应头？它们的作用是什么？

请求头和响应头是HTTP报文的头信息，以k-v格式保存传输。

用于标记浏览器或客户端信息以及报文信息。

### 什么是 HTTP 的消息体？什么情况下会有消息体？

HTTP 的消息体是指在 HTTP 请求或响应中，包含的实际数据部分。它可以携带各种类型的数据，如文本、图像、文件等。

通常HTTP请求方法为：PUT、POST、PATCH都会携带请求体，一般会声明content-type为application/json、file等。

而响应体会更加常见。一个网页、用户信息都是由响应体提供的。

### 什么是 HTTP 重定向？它如何工作？

HTTP重定向是服务端通过提供一个新的location，返回一个重定向状态，让网页向该location发请求的过程。

工作过程：

1. 浏览器向url发起一个请求。
2. 服务器响应一个重定向状态符，并在响应头中提供一个新的location回浏览器。
3. 浏览器获得该location后，向该location发送请求。

## 6. HTTP 安全性

### 什么是 CSRF（跨站请求伪造）？如何防范？

#### 攻击原理

核心知识：

浏览器在你访问一个url时，会将该url的cookies顺带发送。因此，当你访问一个钓鱼网站时，这个网站可能就会向另外的网站执行请求，服务器端会认为这个请求就是你本人执行的。

1. 攻击者诱骗用户访问一个恶意网站或点击恶意链接，而用户已经在浏览器中登录了受攻击的受信任网站。

2. 由于用户的身份和认证信息（如 cookies）仍然有效，受信任网站会接受并执行攻击者伪造的请求，认为这是用户发起的合法操作。

#### 如何防范

**使用 CSRF 令牌**：服务器为每个用户生成一个唯一的 CSRF 令牌，提交请求时必须携带该令牌，服务器验证令牌以确定请求合法性。

**检查 Referer**：验证请求头中的 `Referer` 字段，确保请求来源是受信任的站点。

**双重提交 Cookie**：将 CSRF 令牌存储在 cookie 中，并要求在请求中同时提供此令牌，服务器验证两者一致性。



### 什么是 XSS（跨站脚本攻击）？如何防范？

#### **攻击原理**

- 攻击者将恶意脚本嵌入到网页或 URL 中，当其他用户访问受感染的页面时，恶意脚本在用户的浏览器中执行。
- 这些脚本可以用来窃取用户的敏感信息（如 cookies、会话信息）、篡改网页内容，或以用户身份执行操作。

#### **攻击类型**

1. **存储型 XSS**：恶意脚本被永久存储在服务器上，如在论坛帖子、评论区或数据库中。每当用户访问该内容时，脚本都会被执行。
2. **反射型 XSS**：恶意脚本通过 URL 或请求参数传递给服务器，并立即返回给用户浏览器执行。用户需点击恶意链接或提交恶意表单才能触发攻击。
3. **DOM 型 XSS**：恶意脚本在客户端被执行，浏览器在解析和运行 DOM 时触发，无需与服务器交互。

#### **防御措施**

1. **转义用户输入**：对用户输入的数据进行转义和过滤，避免将其直接插入到 HTML 中执行。
2. **使用 CSP（内容安全策略）**：通过 CSP 限制页面加载的资源，防止恶意脚本被执行。
3. **输入验证和输出编码**：对用户输入进行严格的验证，并对输出的数据进行编码，防止恶意脚本注入。
