# Java 基础扫盲

## 1. 基本数据类型

### 1. 基本数据类型以及包装类

int/Integer 、byte/Byte 、char/Character 、short/Short 、long/Long 、boolean/Boolean

float/Float 、 double、Double

### 2. 基本数据类型和包装类的区别

1. 基本数据类型不是Java对象，没有属性和方法。包装类属于Java对象，有属性和操作的方法。
2. 基本数据类型存放在运行时常量池，包装类会在堆内存中开辟空间。
3. 基本数据类型占用空间比包装类少很多。
4. 对于基本数据类型，直接==比较即可。对于包装类型，需要使用.equals()比较。
5. 基本数据类型有默认值，包装类型默认都为null。

### 3. 包装类型的缓存机制

对于**byte**、Integer、long、short等整型类型，会创建-128~127的缓存数据存放在一个数组当中。

对于character，会创建0~127的缓存数据存放在一个数组当中。

对于boolean类型，会直接返回true或者false。

### 4. 自动装箱和自动拆箱？

首先说说装箱和拆箱是什么：

- 装箱：基本数据类型转为包装类型
- 拆箱：包装类型转为基本数据类型

自动装箱和自动拆箱是java为了更好适配基本数据类型和包装类型的转换而提出来的方案，免去了显式调用装箱和拆箱的操作，降低开发成本。

自动装箱即基本数据类型在需要转为包装类型时，会自动调用valueOf()转为包装类型。

自动拆箱即包装类型需要转为基本数据类型时，会自动调用intValue()转为基本数据类型。

### 5. 为什么浮点数会出现精度丢失？如何解决

在计算机底层中，对数字的计算实际上就是二进制数据的计算。

对于浮点数来说，转为二进制数据的规则是：

- 小数点左边除2进位。
- 小数点右边乘2进位。

对于乘2进位来说，需要小数部分能够刚好乘2等于1，才能够停止，否则就需要继续乘下去。

而大多数是达不到这样的条件的，所以浮点数会在一点截断，被截断的部分就是精度丢失。

解决方案也很简单：不用浮点数，而是使用BigDecimal。

#### BigDecimal为什么能够解决精度丢失问题

要理解这点，就需要从BigDecimal接受什么数据来看。

BigDecimal中可以接收整型数据，浮点型数据，字符串数据。

而我们通常的做法是传入字符串数据，因为字符串数据精度是准确的。

BigDecimal对字符串进行解析，最终数据存储在一个`BigInteger`对象中，并使用`scale`进行小数点偏移，以解决精度丢失问题。

### 6. 超过long的数据如何表示

long支持8字节的存储。如果超过long了，就需要使用BigInteger来表示，BigInteger使用数组来表示大数，因此操作会比基本数据类型的操作更慢。

## 2. 变量

### 1. 成员变量和局部变量的区别

1. 概念：成员变量是对象中的概念，而局部变量是程序中的概念。
2. 保存位置：成员变量保存在对象实例中，局部变量保存在线程方法栈中。
3. 作用域：成员变量在对象中可见，对外部可见性根据权限描述符确定。局部变量只在代码块内可见。
4. 生存时间：成员变量随着对象的创建而创建，死亡而死亡。局部变量在执行完代码块就会消亡。（如果在方法内创建了对象，方法结束后这个对象就会变成垃圾）

### 2.静态变量的作用

静态变量，即被static修饰的变量，也被称为类变量，在类的解析过程被初始化，因此只会被初始化一次。静态变量的作用是可以不创建实例，而是直接通过类调用。通常作用在工具类中，开发者不需要频繁创建实例进行调用。

### 3. 字符串和字符的区别

1. 形式：字符串是通过双引号声明的字符序列。而字符是单引号声明的一个字符。
2. 含义：字符串是一个引用类型，字符是一个基本数据类型。

## 3. 方法

### 1. 静态方法为什么不能调用非静态方法

因为静态方法是属于类变量的，而非静态方法是属于实例对象的，需要使用实例对象去访问。

但是非静态方法可以调用静态方法。

### 2. 静态方法和实例方法的区别

1. 初始化时机：静态方法于类加载的解析阶段进行初始化。而实例方法于创建实例时初始化。
2. 调用方式：静态方法可以直接根据类名调用，实例方法要使用实例变量去调用。
3. 访问域：静态方法不可访问实例变量和实例方法，实例方法可以访问静态方法和静态变量。

### 3. 重载和重写的区别

1. 发生区域：重载是在同一个类发生的，重写是在多个类之间发生的
2. 方式：
   1. 重载允许使用相同方法名，但不同的参数列表或返回值创建一个新方法。
   2. 重写的方法名、参数列表相同。返回值需要是重写方法的同类或子类。抛出的异常需要是重写方法的同类或子类。反问修饰符需大于等于重写方法。

### 4. 什么是可变长参数

- 声明：在参数列表最后一位中，通过...的声明方式去声明。
- 调用：可以通过传入多个同类或子类的对象来调用
- 实质：可变长参数实际上就是一个数组。

## 4. 面向对象基础

### 1. 面向对象和面向过程的区别

我的看法：面向对象和面向过程并不是对立的关系。面向对象是基于面向过程更高级的做法。

面向对象能够比面向过程更**易扩展，易复用，易维护**。

这都是基于面向对象的：封装、继承、多态实现的。

### 2. 创建一个对象用什么运算符，对象实体和对象引用有什么不同

创建一个对象通常使用`new`关键字，也能够通过反射调用构造器创建。

- 存放区域：对象实体被创建后，将会保存在堆区。而对象引用保存在线程栈中，指向该对象所在的内存。
- 引用：一个对象实体可以被多个引用指向，一个对象引用至多可以指向一个对象实体。



### 3. 如果一个类没有声明构造方法，该程序能够正常执行吗

能。所有类都有一个默认的无参构造函数，如果显式声明了构造函数，则没有默认的无参构造函数。

### 4. 构造方法有什么特点，可否被重写

构造函数的声明没有返回值，名称必须与类名相同，在生成实例时自动执行，并且只能执行一次。

构造函数只能被重载，不能被重写。

### 5. 接口和抽象类有什么共同点，区别？

- 共同点：接口和抽象类都可以定义抽象方法。同时他们都不可被实例化。

- 区别：
  - 设计理念：接口是为了规定一组API，而抽象类主要是为了代码复用。
  - 继承和实现：一个类可以实现多个接口，但不能继承多个抽象类/类。
  - 成员变量：接口不能定义成员变量，只能通过`static final`定义常量。而抽象类可以定义实例变量。
  - 方法：接口只能通过default或static来定义方法。而抽象类可以包含抽象方法和非抽象方法。

### 2. == 和 equals的区别 √

== 对基本数据类型，就是比较大小，对对象类型，就是比较对象地址是否相同

equals是只有对象才有的方法。每个对象都有equals方法。

equals在Object的实现实际上就是 ==，但是equals是可以被重写的，也就是每个对象都可以实现自己的equals方法，来做比较。

举个例子就是String类型，它的equals就是比较字符串是否相等，而不是地址是否相同。

### 3. hashCode的作用，为什么需要hashCode √

hashCode通常是为了使一些集合比如HashMap、HashSet等，需要对对象进行哈希取模存入数组更加方便。写在Object里是为了让每个类都有自己的hashCode实现。

### 4. 为什么重写equals必须重写hashCode √

因为在HashMap等集合里面，是先做hashCode，再做equals的。如果只重写equals，不重写hashcode，就会出现hashcode和equals值不一致的现象。比如hashcode选择对id字段进行hash，而equals是根据id和name来确认相同对象的，那么在集合中就会出现差异,如相同id不同名字的对象会在hashcode阶段被认为是相同对象，相当于hashCode比较被穿透了。

### 6. String为什么不可变 *

String不可变的原因是：

1. 存放数据的变量被声明为private final，使得该变量被初始化后就无法被改变。
2. String被声明为final，使得无法被子类破坏。

### 7. 字符串拼接用"+"还是StringBuilder √

如果只是做简单的拼接， 用+就可以，因为底层还是调用的StringBuilder。

### 8. String的equals和Object的equals √

String的equals比较字符串是否相同。

### 9. 字符串常量池是什么？√

字符串常量池是在JVM堆空间开辟出来的一个内存区域，专门用于存放字符串常量。

字符串常量池是JVM为了提升性能和减少内存消耗针对字符串专门开辟的区域，目的是为了比米娜字符串的重复创建。

### 10. String s1 = new String("abc");这句话创建了几个字符串对象？√

创建了1-2个。

如果abc存在于字符串常量池的话，就创建1个，如果不存在，就会创建2个。一个是new的String对象，放在堆区；一个是"abc"对象，被放在字符串常量池。

### 11. String#intern 方法有什么作用? √

intern方法可以直接返回字符串常量池内保存的String对象。

intern()方法的主要作用是确保字符串引用在常量池中的唯一性。

通常是用于在Synchronized上做对象锁。

## 6. 异常

### 1. Execption和Error的区别 *

Execption表示可以捕获处理的异常，通常并不是严重异常。

Error属于程序无法处理的错误 ，不建议捕获该异常。出现这个异常时，JVM通常会选择终止程序。

### 2. 检查异常和不受检查异常的区别

检查异常是不捕获或抛出就无法编译通过的。

而不受检查异常不捕获或抛出可以编译通过，但是一旦发生就会导致线程结束。

### 3. Throwable类常用方法 *

`getMessage()` 返回异常发生时的详细信息

`printStackTrace()` 在控制台上打印 `Throwable` 对象封装的异常信息

`toString()` 返回异常发生时的简要描述

`getLocalizedMessage()` 返回异常对象的本地化信息。使用 `Throwable` 的子类覆盖这个方法，可以生成本地化信息。如果子类没有覆盖该方法，则该方法返回的信息与 `getMessage()`返回的结果相同

### 4. 如何使用try-catch-finally

我们一般分为try、catch、finally代码块。

try需要配合catch或finally或者两个一起，才能工作。

使用方法：

1. try块中放入可能会出现异常的代码块。
2. catch(Execption e)传入需要捕获的异常类，并对这个捕获的异常e进行处理。可以在catch中重新抛出异常。
3. finally是当try块和catch块结束时才执行的代码块。通常用于释放资源，如锁、文件流等。

### 5. finally的代码一定会执行吗

不一定。

情况1：在try块前return的代码，对应的finally不会执行

情况2：在try块中return的代码，假如程序突然结束，finally就不会执行。

### 6. 异常使用有哪些需要注意的地方 *

不要把异常定义为静态变量，因为这样会导致异常栈信息错乱。每次手动抛出异常，我们都需要手动 new 一个异常对象抛出。

抛出的异常信息一定要有意义。

建议抛出更加具体的异常比如字符串转换为数字格式错误的时候应该抛出`NumberFormatException`而不是其父类`IllegalArgumentException`。

## 7. 泛型

### 1. 泛型的作用

1. 代码复用。一套代码可以有多个类的实现。
2. 增强代码的可读性和稳定性。

### 2. 泛型的使用方式有几种

1. 泛型类
2. 泛型接口
3. 泛型方法

### 3. 泛型的通配符 *

对于通配符的get和set，要保证向上转型(安全操作)。

1. 上界通配符 `? extends XXX`
   1. ? extends XXX : 用于声明参数列表，指：传入的参数是XXX或子类，因此不能保证下界，所以只能get，让对象向上转型为XXX，返回参数类型为XXX。
   2. T extends XXX：用于声明签名，指：该方法/类/接口只接受XXX以及XXX的子类。
2. 下界通配符 `? super XXX`
   1. ? super XXX：用于声明参数列表，指：传入的参数是XXX或父类，因此不能保证上界，所以只能set(super XXX)，让XXX向上转型为具体的父类对象。
   2. T super XXX：用于声明签名，指：该方法/类/接口只接受XXX以及XXX的父类。
3. 无界通配符 `?`
   1. 无界通配符可以接收任何泛型类型数据，用于实现不依赖于具体类型参数的简单方法，可以捕获参数类型并交由泛型方法进行处理。

### 4. 泛型擦除是啥

- Java的泛型是伪泛型，这是因为Java在编译期间，所有的泛型信息都会被擦掉，这也就是通常所说类型擦除。
- 编译器会在编译期间会动态地将泛型T擦除为`Object`或将`T extends XXX`擦除为其限定类型 `XXX`。
- 因此，泛型本质上其实还是编译器的行为，为了保证引入泛型机制但不创建新的类型，减少虚拟机的运行开销，编译器通过擦除将泛型类转化为一般类。



## 8. 反射

### 1. 解释一下什么叫反射

反射，在应用上，就是能够根据对象来获取对应的类对象，并使用该类对象进行操作。

比如可以通过类对象获取对应的field、method、interfaces、annotation。以此能够做丰富的动态化处理。

### 2. 反射的优缺点

优点：灵活和动态。能够支持运行时的动态操作，如动态代理等等。

缺点：反射往往会造成性能影响（为什么）。安全性不好，可以通过爆破获取访问受限的实例对象或方法。

### 3. 反射应用场景

1. 动态代理
2. 框架
3. 对对象操作的工具类

## 10. SPI

### 1. SPI 是什么

SPI是调用者规定的一系列接口，这类接口由不同实现者去实现。调用者可根据场合选择需要的实现。

### 2. SPI和API的区别

API是实现者负责规定并实现的接口，调用者直接调用该接口。

SPI是调用者负责规定接口，不同实现者去实现接口。调用者可根据场景选择不同实现者来实现。

### 3. 优缺点

- 优点：在不同场景下能够切换实现，灵活。

- 缺点：需要将实现类全部加载，不能做到按需加载。
