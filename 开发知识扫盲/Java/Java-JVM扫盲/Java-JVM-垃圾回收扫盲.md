# JVM 垃圾回收机制知识点

## 1. 垃圾回收基础
### 什么是垃圾回收 (GC)，为什么需要它？

垃圾回收是JVM内存管理的一个机制，通过垃圾回收能解放开发者对内存的管理，让开发者专注业务。

### 垃圾回收的主要目标是什么？

垃圾回收的主要目标是对不再使用的对象进行自动回收，以解决内存泄露等问题。

### JVM 如何判断一个对象是垃圾？

一个对象是否是垃圾，是根据是否被GC root 直接引用或间接引用决定的。

### 什么是 GC Roots？如何通过它判断对象是否可回收？

GC roots是JVM引用可达性算法的一个核心。该算法规定一系列的根，如虚拟机栈、本地方法栈的引用就是GC root引用。

JVM会从所有线程的GC roots出发，对非垃圾对象进行标记，并对垃圾进行回收。

### 什么是引用？强引用、软引用、弱引用、虚引用有什么区别？

引用，是引用类型对堆对象的一个指针。

- 强引用：Java中绝大多数的引用都是强引用。被GC roots直接或间接强引用的对象绝对不会被回收。

- 软引用：使用SoftReference声明的引用是软引用。软引用是比强引用弱一级的引用。当内存空间足够时，软引用的对象不会被回收，但是一旦内存空间不足，软引用的对象就会被回收。
- 弱引用：使用WeakReference声明的引用是弱引用。弱引用是比软引用弱一级的引用。当一个对象只有弱引用时，该对象随时都可能会被回收。
- 虚引用：虚引用更类似与一个标记，而非一个引用。虚引用必须配合引用队列使用。当JVM要GC一个虚引用对象，会将这个虚引用交给该引用队列。因此可以通过该引用队列来判断一个对象是否将要被回收，来做出对应的操作。

### 什么是内存泄漏，如何通过垃圾回收避免内存泄漏？

内存泄露是：一个对象尽管不再被使用，也不会被回收，也就导致内存空间减少。

如何避免内存泄露：

1. 不再使用的对象，及时将引用释放。
2. 集合类中的对象如果不再使用，调用.clear释放。
3. ThreadLocal会导致内存泄露，当使用结束后调用.remove()清除。

## 2. 垃圾回收算法
### 什么是标记-清除算法？它有什么缺点？

标记-清除算法是通过GC-root对存活对象进行标记，并对未标记的对象进行清除。

缺点：有内存碎片。

### 什么是复制算法？它的优缺点是什么？

复制算法是通过GC-root对存活对象进行标记，将这些存活对象放到另外一块内存空间，并清理整块内存空间。

优点：没有内存碎片。

缺点：空间减少一半。

### 什么是标记-整理法，它如何解决内存碎片问题？

标记整理法是通过GC-root对存活对象进行标记，并将这些对象一个个整理到内存空间的头部。

优点：解决内存碎片问题，同时也不会使内存空间减少一半。

缺点：效率很低。

### 什么是分代收集算法？为什么要采用这种算法？

分代收集算法是将堆空间区分为年轻代和老年代。不同代有不同的收集策略。

因为在一个Java程序中，每个对象都有一个存活周期。有些对象消亡的很快，比如在方法内创建的局部对象。

有些对象会一直存活，比如全局的哈希表。这时候就不能对这些不同存活周期的内存一刀切的回收。

### 什么是年轻代、老年代和永久代？它们的作用是什么？

年轻代是在Java程序运行时经历GC次数少于16次的对象，换句话说，这类对象的存活周期通常会更短。

老年代存放年轻代经历GC次数到达16次的而晋升的对象。这类对象通常会被使用的更频繁。一些大对象也会直接放入老年代。

永久代中存放的是类的信息，这部分是类加载器加载进来的特殊的对象，通常不会被回收，除非类加载器被回收了。

## 3. 垃圾回收器
### 什么是 Serial GC？它适用于什么场景？

Serial GC 是单线程的垃圾回收器。

### 什么是 Parallel GC？它适用于什么场景？

Parallel GC是多线程的垃圾回收器。

### 什么是 CMS GC（Concurrent Mark-Sweep）？它如何减少停顿时间？

CMS GC是一个老年代垃圾回收器，它通过与用户线程并发的方式进行垃圾回收，目的是减少停顿时间。

CMS的执行流程：

1. 先进行初始标记，此时是会STW的，主要是对GCroot的直接引用对象进行标记。
2. 接下来就是并发标记，这个阶段用户线程不会阻塞，GC线程会沿着直接引用对象往下标记。
3. 然后就是重新标记，这个阶段会STW，主要是对并发标记时引用的改变做出改变。
4. 最后就是并发清理垃圾。

### 什么是 G1 GC（Garbage First）？它与 CMS 有何不同？

G1是一个很强大的垃圾回收器，它将堆内存分成一块块region，而非原来的连续内存，在垃圾回收时，优先选取垃圾最多的region进行回收，而不是整块内存回收，大大减少了STW的时间。

## 4. 垃圾回收过程
### 什么是 Minor GC？它发生在什么情况下？

Minor GC 是对年轻代对象的垃圾回收。它发生在Eden区内存空间到达极限的情况。

### 什么是 Full GC？它发生的条件是什么？

Full GC 是对整个堆内存空间的垃圾回收。这个过程通常会十分慢。

发生的条件是：老年代内存空间到达极限的情况。

### 为什么在垃圾回收中会出现停顿？如何减少停顿时间？

在垃圾回收过程中，有一个机制叫做STW，这个机制会在垃圾回收器进行标记时触发，在这个过程中GC 会对引用树进行标记。

减少停顿时间：

选择吞吐量更高的回收器。

增加内存空间大小，减小GC频率。
