# 类加载器相关知识点

## 1. 类加载器基础
### 什么是类加载器，为什么需要类加载器？

类加载器是Java的一个核心类，它负责将编译好的.class文件加载进内存。

### 类加载器的职责是什么？

类加载器负责将.class文件以字节流的形式读入并加载进内存。

### 类加载器的加载过程是什么样的？

1. 通过全类名获取.class文件的二进制字节流。
2. 将字节流所代表的静态结构转换为方法区的运行时数据结构。
3. 在堆中创建Class对象，作为访问方法区这个数据的入口。

### 什么是类加载的双亲委派模型？

双亲委派模型是ClassLoader中的loadClass方法。

其中规定了类首先将类加载的操作交给自己的父类加载器，

也就是会一直递归到最顶层的类加载器去查询，

如果找不到，再一层一层往下查找该类。

### 如何理解类加载器的父子关系？

类加载器的父子关系最主要是服务于双亲委派模型的。

在loadClass中，一个类的查找是首先交给父类去做的。

### 类加载器为什么不能加载已经被加载的类？

在CLassLoader中有一个方法专门用来判断该类是否已经被加载，

在loadClass中使用了这个方法，这是类加载器不能加载已经被加载的类的直接原因。

而根本原因就是：已经加载的类就没有必要再加载一遍了。

## 2. 类加载器的种类
### 什么是启动类加载器（Bootstrap ClassLoader）？

启动类加载器是Java中最顶层的类加载器。它的实现是通过C++写的。

启动类加载器负责加载rt.jar包中的类，java.lang、java.util是在这里面。

### 什么是扩展类加载器（Extension ClassLoader）？

扩展类加载器是第二层的类加载器，

扩展类加载器负责ext目录下的jar包和类。

在Java9以后，扩展类加载器被废除。

### 什么是应用类加载器（App ClassLoader）？

应用类类加载器是第三层的类加载器，

应用类加载器负责将classPath下的所有类的加载。

### 什么是自定义类加载器，它如何工作？

自定义类加载器是开发者创建的集成ClassLoader或其子类的类加载器。

通常需要重写findClass来工作。

自定义类加载器也可以通过重写loadClass来打破双亲委派机制。

### 类加载器的层级结构是怎样的？

BootStrapClassLoader -> ExtensionClassLoader(Java9废除) -> AppClassLoader ...

### 为什么需要自定义类加载器？

自定义类加载器可以做很多事情。

首先是可以加载磁盘其他位置的类，甚至是网络中的类，

其次，也是十分重要一点的是，可以打破双亲委派机制。

## 3. 类加载的过程
### 类加载的过程包括哪些主要阶段？

加载-连接-初始化。

### 类加载的不同阶段如何配合实现加载的？

加载：将静态的.class文件通过字节流的方式读取进内存。

验证：验证该类是否符合Java类的特征。

准备：为类变量分配内存并初始化。

解析：将符号引用转为直接引用。

初始化：执行static静态代码块，为类变量赋值。

### 什么是类的初始化？它与类加载有什么关系？

初始化是执行初始化方法`<clinit>`的过程。是类加载的最后一步。

### 类加载失败时，JVM 会抛出什么异常？

ClassNotFoundExecption

ClassFormatExecption

UnSupportedClassVersionError

。。。

## 4. 双亲委派模型
### 什么是双亲委派模型，它如何解决类加载冲突？

双亲委派通过将类的加载先委托给父类加载器进行加载，如果没有再在本类加载的规则来解决冲突。

### 双亲委派模型的优缺点是什么？

优点：

1. 保证类的安全性和可靠性
2. 保证类不会被重复加载

缺点：

1. 无法保证隔离性。出现钻石依赖的问题时就会出问题。

### 如何通过自定义类加载器来破坏双亲委派模型？

## 5. 类加载器与类的唯一性
### 类加载器是如何确保类的唯一性的？

类的全限定名和类加载器确认一个类。

### 为什么同一个类加载器加载的类是唯一的？

因为类加载器在加载类时会先判断该类是否已经存在。

不同的类加载器的结果是不一样的。

## 10. 类加载器的常见问题与解决方案
### 为什么在 Tomcat、Jetty 等容器中，类加载器可能出现不一致的问题？

因为重写了类加载器的loadClass。我们知道，Tomcat和Jetty是web容器，也就是会有多个服务在容器里运行的情况。

双亲委派机制中有一点就是类不能被重复加载，这一点在单个服务中是成立的，但是在Web容器时就会出问题。

假如服务1和服务2是同一个程序，但是依赖版本不同，这时候，尽管类名相同，但是实现会不同。因此Web容器打破了双亲委派机制，让类现在本服务内部的类加载器中查找，没有再交给父类加载器。
