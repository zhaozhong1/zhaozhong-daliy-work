# 事务扫盲

## 事务隔离级别是怎么实现的？

### 事务有哪些特性？

1. 原子性
2. 隔离性
3. 一致性
4. 持久性

### 并行事务会引发什么问题？

### 脏读

脏读即事务会读到其他未提交事务的改变。

### 不可重复读

不可重复读即事务会读到其他已提交事务的改变。

### 幻读

幻读即事务会读到添加的数据。

## 事务的隔离级别有哪些？

1. 读未提交
2. 读已提交
3. 可重复读
4. 串行化

## Read View 在 MVCC 里如何工作的

### 1. 首先说说Read View的结构

Read View中包含了一个活跃事务列表、版本链尾id、版本链头id、以及创建rv的事务id。

### 2. ReadView工作在Undo log中，以下是工作流程

Undo log中每一条语句都记录了事务id，ReadView主要依赖于这个事务id进行版本控制。

判断一个语句是否可见，是通过上面提到的ReadView来实现的。

每次查询，都会基于ReadView在Undo log查找可见版本。

流程如下：

1. ReadView首先会查询该事务id是否为创建ReadView的事务id，是，则可见。否，则下一步。
2. 再查询该事务id是否小于最大已提交事务id(版本链尾id)，是，则可见。否，则下一步。
3. 再查询该事务id是否大于预创建事务id(版本链头id)，是，则该版本不可见，进行下一版本，否，则下一步。
4. 最后判断该事务id是否在活跃事务列表中，是，则不可见，进行下一版本。否，则可见。

## 可重复读是如何工作的？

可重复读是通过MVCC + next-key-lock工作的。

其中，通过MVCC解决了脏读和不可重复读的问题，通过next-key-lock解决了部分幻读问题。

## 读提交是如何工作的？

读提交是通过MVCC工作的，通过MVCC解决了脏读问题。

与可重复读的MVCC不同的是，读提交的ReadView是在每次执行sql中获得的，而可重复读的ReadView是在事务开始时获得的。

##  MySQL 可重复读隔离级别，完全解决幻读了吗？

并没有。

有两种情况会导致幻读。

### 情况1

在事务中：

1. 通过快照读，查询到正常的数据。
2. 另外一个事务插入了一条数据，提交。
3. 本事务更新了这个数据，发现更新成功。
4. 再次快照读，发现这个数据出现了。

### 情况2

在事务中：

1. 通过快照读，查询到正常的数据。
2. 另外一个事务插入了一条数据，提交。
3. 通过当前读，读到这个插入的数据，出现幻读。
